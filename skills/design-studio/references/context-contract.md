# Context contract

Record: task mode (new-design/audit/implement/pattern), brief source, preference source, system source, screen source, repo/stack evidence and capabilities. Unknown fields stay unknown. A path mentioned by a user is not proof that its contents were read.

## Read and prioritize

Read only user-selected or task-relevant files. Find existing equivalents before creating `design/` files. Use current project brief/system/screens/decisions/lock, relevant components and repo instructions. Recover missing prior context before continuing a prior project.

Visual priorities: explicit current request → agreed project system → personal preferences → library suggestions. A request conflicting with an agreed shared rule requires impact assessment and a recorded decision; clarify when the intended override/scope is uncertain. Preserve prior rules elsewhere.

Technology: existing repos keep framework/language/styling. New projects use HTML/CSS/JavaScript for simple pages/prototypes or ReactJS/JavaScript/plain CSS for component-rich stateful UI; record why. Do not introduce TypeScript, Tailwind or Next.js for a new project without a user request. An explicit migration request is a separate scoped decision, not a preference inferred from “I like React”.

## Sources and capabilities

Evidence: observed code, actual screenshot, reachable page, research supplied. Assumption: unverified hypothesis. Decision: agreed choice. Keep these distinguishable.

Use repository files when available. Outside repos, ask for a shared folder location supported by the host; suggest `UI-UX-Studio/preferences.md` and `UI-UX-Studio/patterns/`. Treat packaged catalog as seed, not mutable personal data. In chat-only mode provide exportable content and say persistence is unverified. Record actual locations in the brief.

If a required file/tool is absent, request it or explicitly narrow the output. Do not claim unseen interactions, automatic sync, file saving, browser checks or research. Do not search unrelated user files for a missing project.
