# UI checklist

## Visual system
Clear primary task and content hierarchy; purposeful type scale; semantic colors; readable spacing; consistent components/variants. Reuse pinned patterns; record exceptions.

## Responsive and content
Use breakpoints driven by layout/content. Check narrow/wide views, long/translated labels, empty and dense content, errors and loading. Avoid content clipping and accidental page overflow; table scroll may be intentional.

## Interaction and accessibility
Visible labels/focus, keyboard-operable controls, meaningful link/button names, non-color feedback, readable text and contrast checks when actual colors exist. Respect reduced-motion preferences if adding motion. Distinguish disabled, pending, error and success. Do not certify compliance from visual appearance.

## Evidence
Separate designed/specification states from states actually rendered/tested. Screenshot or prototype quality does not prove backend behavior. List dependencies and unresolved values. For relevant web standards use current primary W3C/WAI documentation; do not quote large passages.

References: https://www.w3.org/WAI/test-evaluate/preliminary/ and https://www.w3.org/WAI/tutorials/forms/labels/ (consulted 2026-10-12).
