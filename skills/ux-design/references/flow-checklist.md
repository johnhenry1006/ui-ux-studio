# Flow checklist

- Match primary user task/outcome; distinguish real evidence, hypothesis and decision.
- Define entry points, destinations, actions and minimum data.
- State conditions for transitions, validation timing, retries, cancellation and back.
- Preserve entered data where appropriate; avoid duplicate pending submissions.
- Differentiate empty dataset, no results and load failure.
- Specify permission/authorization restrictions when relevant without inventing backend rules.
- Define logical keyboard/focus and accessible feedback; native controls where possible.
- Make navigation work on narrow layouts without losing task context.
- Ask about business rules only when needed; mark unknown rules rather than invent them.
- Define measurable validation and actual evidence limits. User testing recommendations are not completed studies.
